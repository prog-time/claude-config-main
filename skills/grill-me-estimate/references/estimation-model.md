# Модель расчёта сметы

Читается на шаге 5 перед каждым расчётом. Все числа ниже — дефолты;
менять их можно только по прямой просьбе пользователя, и тогда это
фиксируется в смете.

## 1. Ставка

| Параметр | Значение |
|---|---|
| Месячная ЗП | 150 000 ₽ |
| Рабочих часов в месяце (среднее) | ~165 ч |
| **Часовая ставка** | **910 ₽/ч** (150 000 / 165 ≈ 909, округлено) |
| Рабочий день для пересчёта в срок | 8 ч, из них продуктивных 6 ч |

Срок в рабочих днях = итоговые часы / 6 (округлить вверх).

## 2. Оценка подзадачи — PERT

Для каждой подзадачи три оценки **ручной** работы (как если бы делал
без AI):

- **O** — оптимистичная (всё пошло гладко);
- **M** — наиболее вероятная;
- **P** — пессимистичная (типичные грабли случились).

`E = (O + 4M + P) / 6`

Правила здравого смысла: `P ≥ 2 × O`; если `P > 3 × M` — подзадача
слишком мутная, задай по ней ещё вопрос или раздроби.

## 3. Коэффициенты Claude Code

`E_cc = E × k`. Коэффициент уже включает время на постановку задачи
агенту, ревью и правку его вывода.

| Тип работ | k | Примеры |
|---|---|---|
| `boilerplate` | 0.3 | CRUD, скаффолдинг, DTO, миграции по готовой схеме, конфиги |
| `logic` | 0.5 | Типовая бизнес-логика, валидация, API-эндпоинты, формы |
| `tests` | 0.4 | Юнит- и интеграционные тесты по готовому коду |
| `docs` | 0.3 | README, API-доки, комментарии, changelog |
| `refactor` | 0.6 | Рефакторинг, обновление зависимостей, перенос кода |
| `integration` | 0.8 | Внешние API со слабой документацией, легаси, отладка окружения |
| `debug` | 0.8 | Поиск сложных багов, гонки, производительность |
| `design` | 1.0 | Архитектура, проектирование БД, исследование решений |
| `manual` | 1.0 | Созвоны, согласования, ручной QA, деплой, приёмка, code review |

Неизвестный тип → `k = 1.0`.

## 4. Буфер риска

Применяется к сумме часов (отдельно в обоих сценариях).

| Неопределённость | Буфер | Когда |
|---|---|---|
| Низкая | +10% | Всё понятно, стек знаком, макеты/ТЗ есть |
| Средняя | +25% | Есть допущения, одна-две внешние интеграции |
| Высокая | +50% | Много допущений, легаси, нет ТЗ, допрос не доведён до конца |

## 5. Коэффициент срочности

| Срок | Множитель |
|---|---|
| Обычный | ×1.0 |
| Сжатый (нужно быстрее комфортного темпа) | ×1.3 |
| Горящий (переработки, выходные) | ×1.5 |

Множитель применяется к деньгам, не к часам.

## 6. Итоговая формула

```text
H_manual = Σ E                       × (1 + буфер)
H_cc     = Σ E_cc                    × (1 + буфер)
Цена     = ceil_1000(H_cc × 910 × срочность)
```

`ceil_1000` — округление вверх до 1 000 ₽. В смете показываются оба
сценария (`H_manual` для сравнения), цена считается по `H_cc`, если
пользователь не сказал иначе.

## 7. Пример

| Подзадача | Тип | O | M | P | E | k | E_cc |
|---|---|---|---|---|---|---|---|
| Модель и миграция платежей | boilerplate | 1 | 2 | 4 | 2.2 | 0.3 | 0.7 |
| Интеграция с ЮKassa | integration | 4 | 6 | 12 | 6.7 | 0.8 | 5.3 |
| Webhook + смена статуса | logic | 2 | 3 | 6 | 3.3 | 0.5 | 1.7 |
| Тесты | tests | 2 | 3 | 5 | 3.2 | 0.4 | 1.3 |
| Деплой и приёмка | manual | 1 | 2 | 3 | 2.0 | 1.0 | 2.0 |
| **Итого** | | | | | **17.4** | | **11.0** |

Буфер средний (+25%): `H_manual = 21.8 ч`, `H_cc = 13.8 ч`.
Цена: `13.8 × 910 = 12 558` → **13 000 ₽**. Срок: `13.8 / 6` → 3 рабочих дня.
